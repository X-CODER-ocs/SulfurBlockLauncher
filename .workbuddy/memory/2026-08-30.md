### ✅ 重大突破：x64 .NET + Rosetta 2 绕开 macOS 27 的 arm64 CoreCLR 阻断
- 根因澄清：`0x8007000C`(ERROR_INVALID_ACCESS) 是 .NET **arm64 原生** JIT/内存路径
  在 macOS 27 beta(26A5388g) 上特有，与代码签名/hardened runtime **无关**——
  ad-hoc 重签（带 allow-jit 授权、去 hardened runtime）**依然失败**，codesign 路线已证伪。
- 验证：连最新 10.0.400 SDK（runtime 10.0.11）的 **arm64** 版同样 `0x8007000C`，
  说明微软目前没有任何 .NET 10 运行时支持 macOS 27。
- 解法（自研绕开，非官方补丁）：装 **osx-x64** SDK，由 Rosetta 2 转译运行。
  x64 走的是不同代码路径，不再命中 macOS 27 的 arm64 bug。
  - 已装到 `~/dotnet11x64`（10.0.400，RID=osx-x64）。
  - `~/dotnet11x64/dotnet --version` → `10.0.400` ✅
- 构建验证（全部 0 error）：
  - `dotnet restore src/Portal.Desktop/Portal.Desktop.csproj -r osx-x64` ✅
  - `dotnet build   src/Portal.Desktop/Portal.Desktop.csproj -r osx-x64 -c Debug` ✅（产出 Portal.Desktop.dll + 全部依赖）
  - `dotnet publish ... -r osx-x64 -c Debug [--self-contained true]` 产出可运行 apphost（Mach-O x86_64）。
- ✅ 已将 `~/dotnet11x64` 前置到 PATH（写入 `~/.zshrc` 与 `~/.zprofile`），
  现在裸 `dotnet` 在新 shell 即解析到 x64 SDK（验证：`dotnet --version`→10.0.400，裸 `dotnet build` 0 错误）。
- 已加 `global.json` 固定 SDK 10.0.400（rollForward=latestFeature）。
- 出包产物：
  - 自包含可运行：`src/Portal.Desktop/bin/Debug/net10.0/osx-x64/publish/`（apphost + 捆绑 x64 运行时）。
  - `.app` 套装：`src/Portal.Desktop/bin/Debug/net10.0/osx-x64/Portal.Desktop.app`
    （apphost 已带 allow-jit 授权重签；codesign 的 .deps.json/"no resources" 严格告警对本地启动无害）。
- ⚠️ 经 Rosetta 转译（x64），性能低于原生 arm64；GUI 需在真实显示器下启动（沙箱无显示，未能实跑验证窗口）。
- `Portal.Desktop` 实为跨平台 WinExe：非 Windows 宿主下 TFM=net10.0 并定义 MACOS，
  可在 macOS 出 osx-x64 包（DotNet.Bundle 未自动生成 .app，但 apphost 可直接跑）。
